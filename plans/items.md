# 物品

## 存储介质

所有存储介质物品须在物品详情 `item.userData["display"]["Lore"]` 显示当前剩余可用容量，包含两行：

- `剩余种类数：<剩余可容纳的新资源种类数>`
- `剩余总数量：<剩余容量> 单位物`

剩余种类数 = 介质类型上限 − 当前实际占用类型数；剩余总数量 = 介质总容量 − 当前实际已用容量，均以该介质自身的服务端权威数据计算，不使用整个网络的汇总值。类型数为 0 时，若数量容量仍有余量，仍可追加已存在的资源类型。库存预留尚未取出时仍占容量，预留/释放本身不改变这两项剩余值。

纯物品介质按物品个数显示剩余总数量；含流体时沿用存储服务的单位物换算，以整数容量尺度计算并准确展示，不把 mB 直接当作物品个数，也不向上取整夸大容量。数值显示完整精度，不用 K/M 等缩写。例如空的小型单面磁带显示 `剩余种类数：12`、`剩余总数量：1728 单位物`。

Lore 是可重建的展示信息，不是介质身份、内容或容量的权威存档。首次初始化、实际存取成功及介质恢复后更新权威容量摘要并标记展示待刷新，不要求每笔存取都写回真实物品。有人查看时按预算合并刷新；无人查看且没有交接时不周期性写回。从驱动器取出或按既定规则生成掉落物时，应携带与最新已提交内容一致的详情。更新仅替换本模组管理的容量行，保留自定义名称、其他 Lore 与无关 `userData`。

仅本模组存储介质受管理的动态容量行不参与资源身份比较，不能全局忽略 `display` 或其他 Lore；介质实例还须由持久稳定 ID 区分。身份比较与完整物品还原分离，ID 携带、管理行识别和旧数据迁移由 12-02 落实后接入。具体刷新、交接与分阶段验收见 [存储介质容量 Lore：身份与刷新实施契约](technical_notes/medium_lore.md) 及任务 05、06、11、12、14；本条为新增待实现要求。
