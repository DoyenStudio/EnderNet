# 物品

## 存储介质

所有存储介质物品须在物品详情 `item.userData["display"]["Lore"]` 显示当前剩余可用容量，包含两行：

- `剩余种类数：<剩余可容纳的新资源种类数>`
- `剩余总数量：<剩余容量> 单位物`

剩余种类数 = 介质类型上限 − 当前实际占用类型数；剩余总数量 = 介质总容量 − 当前实际已用容量，均以该介质自身的服务端权威数据计算，不使用整个网络的汇总值。类型数为 0 时，若数量容量仍有余量，仍可追加已存在的资源类型。库存预留尚未取出时仍占容量，预留/释放本身不改变这两项剩余值。

纯物品介质按物品个数显示剩余总数量；含流体时沿用存储服务的单位物换算，以整数容量尺度计算并准确展示，不把 mB 直接当作物品个数，也不向上取整夸大容量。数值显示完整精度，不用 K/M 等缩写。例如空的小型单面磁带显示 `剩余种类数：12`、`剩余总数量：1728 单位物`。

Lore 是可重建的展示信息，不是介质身份、内容或容量的权威存档。首次初始化、实际存取成功及介质恢复后更新权威容量摘要并标记展示待刷新，不要求每笔存取都写回真实物品。有人查看时按预算合并刷新；无人查看且没有交接时不周期性写回。从驱动器取出或按既定规则生成掉落物时，应携带与最新已提交内容一致的详情。更新仅替换本模组管理的容量行，保留自定义名称、其他 Lore 与无关 `userData`。

仅本模组存储介质受管理的动态容量行不参与资源身份比较，不能全局忽略 `display` 或其他 Lore；介质实例还须由持久稳定 ID 区分。身份比较与完整物品还原分离，ID 携带、管理行识别和旧数据迁移由 12-02 落实后接入。具体刷新、交接与分阶段验收见 [存储介质容量 Lore：身份与刷新实施契约](technical_notes/medium_lore.md) 及任务 05、06、11、12、14；本条为新增待实现要求。

## 样板

**工厂样板** (endernet:factorical_template)
- 唯一样板物品。移除独立的 `endernet:crafting_template`（合成样板）物品；“合成样板”只表示编码模式（2026-10-04 User 定案）。
- 名称固定为“工厂样板”；不写入自定义名称或 `customTips`，配方说明写入 `userData.display.Lore`，按以下格式逐行显示： `§r§f制作： <第一项产物名>\n§r§f使用：\n§r§7 - <原料名>x<数量>...`，相同资源键的原料合并数量，按首次出现顺序逐行显示（如 `铜锭x9`）。物品名取 `Item.GetBasicInfo().itemName`；流体保留资源标识。
- 配方模式保存在物品 `userData` 中，两种模式均由样板终端写入同一工厂样板物品。
- **合成样板模式**：记录完整合成配方，放入装配仓的样板槽 10～18 使用；装配仓直接使用编码配方，不做工作台配方校验。装配仓拒收工厂模式、空白及损坏样板。
- **工厂样板模式**：记录自定义配方，放入总线样板接口使用；不能用合成模式的编码件提供外部加工配方。
- 堆叠上限：**64**（User 2026-10-02 定，用于样板终端的输入槽）。不同配置样板的引擎分堆行为仍待游戏内验证，见 [欠账台账](tasks/00-欠账台账.md)。
- 本次不自动转换旧物品或修改旧存档库存；已有独立合成样板需要用工厂样板在样板终端重新编码。


## 内存
放置在**内存槽**中为网络提供内存。堆叠上限：**1**（2026-10-03 定）。
网络的内存容量由网络内**内存槽里实际插着的内存条**合计而来（各型号容量见下）；
内存槽**只收内存条**，其他物品放入一律拒收（2026-10-03 定）。
单根容量即字节数，订单配方树叶子根原料每 1 单位物占 1 B，详见 [配方运行内存](concepts.md#配方运行内存)。
