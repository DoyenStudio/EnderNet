> 2026-11-15 实施版。用户已批准按本方案制作材料、物品、方块和生成规则；以当前 [方块](blocks.md)、[物品](items.md) 与 `common/definitions.py` 为基准，数据在 `common/materials.py` 中统一定义。资产与配方已生成，运行逻辑和游戏验收进度分别记录，不以生成文件代替实测结论。
>
> 保留原稿的末地材料主题、末地谐振矿石，以及末影粉和充能谐振水晶的两条手工配方。已有设备功能、容量、带宽、耗能与未定规则仍以原规格为准。本方案不把研发替身数值定为正式规则。

已落地 25 种材料、3 台机器、72 条工作台配方、2 条熔炉配方和 8 条机器配方。完整离线检查与 MCDK 实机结果见 [材料系统验收](acceptance/materials/README.md)，图标和机器外观见 [贴图预览](acceptance/materials/materials-preview.png)。

## 1. 总体思路与进度

采用 AE2 的「水晶材料 → 三类芯片 → 功能核心 → 网络设备 → 自动化扩产」结构，换成 EnderNet 的末地风格。配方体现用途：存货用收束核心，取货用展开核心，计算用运算芯片，复杂机械用工程芯片。

默认定位为**到达末地之后发展的仓储科技**：采矿取得第一批谐振水晶，末地石用于机壳骨架，石英用于白色饰面，紫珀块用于进阶结构，紫水晶用于紫色电路与光学部件，末影之眼用于控制与远距连接。基础仓储不消耗钻石；自动化才开始使用钻石；下界之星只用于终局高密磁带。若以后希望末地前开局，应另加有成本的材料获取路线，不直接移除这条主线。

| 阶段 | 玩家目标 | 主要解锁 |
| --- | --- | --- |
| 备料 | 去末地采矿，准备末地石、石英、黑石与紫水晶碎片 | 机壳、发电机、压印机、逻辑芯片 |
| 手动仓储 | 把箱子库存集中到终端 | DOS 控制器、8 位基带、驱动器、磁带、通用/合成终端 |
| 自动物流 | 农场自动入库、机器按需补货 | 小型控制器、存取货口、16 位基带、软盘/硬盘 |
| 自动生产 | 自动制造芯片、材料和设备 | 样板终端、样板接口、装配仓、并行处理器、内存 |
| 扩建 | 提高线路容量和远距连接能力 | 32 位基带、致密光缆、P2P、无线连接器 |
| 大规模仓储 | 归档巨量同类资源 | 高阶硬盘、数据库高密磁带 |

### 配方记法

- `工作台`：本草案统一为无序配方；`A×2` 表示占两个原料格。每条最多 9 格，后续如改有序摆法，材料与产量保持一致。
- `熔炉`：使用原版燃料规则，表中不重复列燃料。`充能器`、`压印机`：使用本文件新增的机器配方。
- 表格中的产物默认 **1 件**，批量产出明确写 `×N`；消耗原料全部列出，不存在隐含返还物。
- 原版材料中「红石」指红石粉，「萤石」指萤石粉，「石英」指下界石英，「紫水晶」统一使用紫水晶碎片；原稿的「紫颂块」按原版**紫珀块**理解。
- 新材料暂以中文名作为唯一设计名称；已有物品保留当前 ID，包括 `harddisk_16`、`factorical_template`、`factoric_terminal_*` 的现有拼写。
- 外观与配方对应到**整棵合成树**：白色外壳的石英应来自机壳或光学组件，不能仅用“芯片的硅片也是石英烧的”解释；继承组件材料即可，不要求每台机器重复加入同一种原料。只对应主要外壳、明显色带和大块功能结构，不逐个追究像素阴影与状态指示灯。

## 2. 原料与基础材料

### 2.1 原料来源

| 原料 | 建议来源与作用 |
| --- | --- |
| 末地石 | 原版末地岛；机壳内部骨架，外面的冷白饰面由石英承担 |
| 石英 / 铁锭 | 石英做白色饰面和硅片；铁做银灰边框、支架、触脚 |
| 黑石 | 原版下界；强化机壳与小型控制器的深灰主体，不额外引入新的合金 |
| 紫珀块 | 原版紫颂果 → 爆裂紫颂果 → 紫珀块；高级结构，可通过种植供应 |
| 紫水晶碎片 | 原版紫水晶洞；紫色电路、样板部件、致密线缆和光学玻璃 |
| 青金石 | 原版采矿；流体接口明显的深蓝色带，通过流体密封组件统一引入 |
| 青色染料 | 原版青色染料；谐振玻璃的青蓝色，沿光学部件进入线缆、终端和控制器，不以钻石或海晶石强行增加前置 |
| 木板 | 任意原版木板；磁带的棕色卷轴外壳，木材品种不改变成品颜色 |
| 末影珍珠 / 末影之眼 | 原版获取；末影粉、控制器、无线部件 |
| 末地谐振矿石 → 谐振水晶 | 铁镐及以上开采，普通掉落 1 个谐振水晶，精准采集得矿石，矿石可熔炼为 1 个水晶。实施参数：**无限世界中新生成的末地区块**，`the_end` 群系、Y=32～72，每区块尝试 6 条最多 8 块的矿脉，只替换末地石；空洞处不生成。当前时运不增产，不补写旧区块；旧有限世界与超平坦世界不在自然生成保证范围内 |
| 金 / 红石 | 金用于金黄功能件和触点，红石用于电路；红石与紫水晶共同解释能源口的紫红发光部件 |
| 钻石 | 工程芯片；自动化与高级设备的门槛 |
| 下界之星 | 高密归档组件；不作为普通联网与自动化的前置 |

第一版不额外增加铜线、锡板、橡胶等材料体系，也不增加必须寻找陨石或随机战利品才能获得的压印模具。谐振水晶先以采矿供给；可再生晶体生产属于后续扩展，不作为本版配方成立的条件。

## 3. 新增的三台机器

新增 **2 台配方处理设备 + 1 台启动电源**。三台均是独立机器，不是 EnderNet 网络节点，不占网络带宽、不要求控制器，不让网络断电阻止发电或基础加工。通过现有 transferlib 公共能源接口衔接；前期相邻摆放即可，不额外增加电线。

| 机器（建议 ID） | 工作台投入 → 产出 | 职责与建议数值 |
| --- | --- | --- |
| 谐振充能器 `endernet:resonance_charger` | 末地机壳×1 + 铁锭×2 + 红石×2 + 谐振水晶×2 → 1 台 | 一个原料槽、一个成品槽；每个水晶 4 秒、32 FE/t，即 2560 FE/次；待机 0 |
| 谐振压印机 `endernet:resonance_inscriber` | 末地机壳×1 + 活塞×2 + 铁锭×2 + 谐振水晶×2 + 红石×1 → 1 台 | 三个原料槽、一个成品槽；粉碎、压印、封装均 4 秒、32 FE/t，即 2560 FE/次；待机 0 |
| 谐振燃料发电机 `endernet:resonance_generator` | 末地机壳×1 + 熔炉×1 + 铁锭×2 + 红石×2 + 谐振水晶×1 → 1 台 | 单燃料槽，只收煤炭/木炭；64 FE/t，单份燃烧 1600 tick，合计 102400 FE；内部缓存建议 32000 FE |

发电机和充能器的当前 UI 保留 SkyBlueTech `ThermalGeneratorUI` / `ChargerUI` 的仪表布局：发电机显示燃烧火焰与能量条；充能器显示能量条、闪电进度及 26 px 成品输出槽。背景和槽位采用装配仓的 EnderNet 样式，不引入装配仓的 `stat_bar` 网络状态条。三台新机器统一采用充能器的 `title/title_text` 标题底板样式；ring 为白色常显框，不随工作状态变色、闪烁或隐藏，压印机四个槽位也使用同样白框。两台机器的能量条常态均为紫色，保留渐变；充能器低电量时仍使用黄色、红色告警。压印机保留原有三种模式与数值显示。当前实现与实机证据见 [生产设备 UI 验收](acceptance/production-ui/README.md)；材料验收目录中的旧截图保留为初版历史记录。

这些是首轮调参起点，按 20 tick/s 计算。发电机的一台输出经能源接入口换算后上限为 32 EN/t，供加工机器时直接用 FE。扩产可并联多台发电机或换其他模组电源，不强行把这一功率写成现有网络设备的耗能。

### 机器交互与自动化约定

- 充能器、压印机六面接收 FE；发电机六面输出 FE，六面合计不超过 64 FE/t，多个接收端公平分配。发电机不能被反向充电。
- 压印机有「粉碎 / 压印 / 封装」三种手动选定模式。自动输入按当前模式过滤、分配到对应原料槽，玩家可建专用机器阵列；模式切换不吞原料，正在加工时禁止切换。
- 两台加工机器的自动输入只进原料槽，自动提取只出成品槽；发电机自动输入只进燃料槽。原版漏斗即可完成早期半自动化，不依赖尚未造出的样板接口。
- 加工缺电时保存进度、暂停；输出满时暂停且不耗电。开工保留本批原料，完工时原料扣除与成品写入必须一次提交，存档和拆机不能复制或吞掉原料。
- 发电缓存满时暂停燃烧进度，不继续白烧煤；拆机取出未燃烧物品，已燃烧进度和 FE 不可兑换成新煤。
- 首台发电机和压印机都不需要芯片、充能水晶或高级机壳，因此可以在联网前做出全部芯片；充能器是节料升级，不是启动必需品。
- 加工设备在订单中属于外部工厂：工厂样板写消耗材料和产物，机器通过物品物流接样板接口，电力由外部供给。不要把机器加工配方伪装成工作台配方交给装配仓。

## 6. 开局与扩产路径检查

### 6.1 最小仓储启动包

准备原版工作台、熔炉和燃料后，按顺序完成：

1. 采到谐振水晶，准备石英、黑石、紫水晶碎片和少量青色染料；先制造末地机壳、谐振燃料发电机和谐振压印机。紫珀内衬和强化机壳留给后续升级，不作为首次联网前置。
2. 发电机直接给压印机供电；粉碎石英、熔炼硅片，生产逻辑芯片。首批充能水晶用已有的手工配方取得。
3. 制作 DOS 控制器×1、8 位基带×1、能源接入口×1、存储驱动器×1、小型单面磁带×1、通用终端（光缆）×1、末影玻璃光缆若干。
4. 控制器必须紧贴基带，能源接入口和驱动器经基带/光缆接入；终端挂在玻璃光缆上，磁带插进驱动器，发电机贴能源接入口供电。
5. 将物品从终端存入网络，再制作充能器节省材料，升级合成终端和更快的介质。

这里不需要工程芯片、内存、样板终端或装配仓；没有任何基础材料必须先由网络订单制造。核心、原料机器与电源的配方均可手动完成。

这是一条**配方依赖可达**的启动路线，不代表已完成游戏供电验收：光缆、基带、能源接入口等既有能耗缺项仍受 R10 管理，不能将未知耗能视为 0 后声称一台发电机必定足够。正式开放生存时应补齐相关规则并按实测总功率配置电源。

### 6.2 第一条自动化产线

1. 手动制造小型控制器替换 DOS，准备样板终端、空白工厂样板、内存槽和至少一根内存。
2. 制作并行处理器连接器与并行处理器；处理器经连接器接网，不直接贴光缆冒充连接成功。
3. 用装配仓承接工作台配方，用总线样板接口承接压印机、充能器和熔炉配方。燃料与电力保持独立供应；需要网络补燃料时按既有工厂样板规则显式记录。
4. 第一批可手动预制逻辑/运算/工程电路和硅片，先自动封装芯片；随后补齐粉碎、熔炼、压印工序，避免一次调试整条链。
5. 扩产时增加机器和并行处理器；按订单实际叶子原料需求升级内存，不宣称一根 128B 能执行任意高阶设备订单。

一台基础发电机只有 32 EN/t 的等效功率，而现有并行处理器工作态自身已需 32 EN/t；自动合成启动前必须扩大发电能力，不能沿用最小仓储电源就假定整网够电。连接器、内存、终端和装配仓另计。

## 7. 配方落地边界与验收

### 7.1 升级与数据安全

- 本次采用**独立制作配方**：不消费旧控制器、接口、驱动器、终端、带数据工具、介质或工厂样板。只有无库存和业务配置的基带、光缆、内存作为成品递进原料，避免原生工作台只按 ID 匹配时吞掉状态。
- 该约束已直接体现在第 4 节的实际配方和生成数据中；玩家工作台、合成终端与自动装配都使用同一套无数据组件输入，不另开放带状态成品升级的旁路。
- 如将来新增保留旧设备数据的升级，必须另行实现服务端权威状态检查及迁移，不能只在预览或编码阶段检查一次。现有装配仓直接执行已编码样板的规则不变。
- 新做出的配置卡、无线连接工具、终端、接口和连接器均为默认状态；样板必须为空白。带编码样板不能当普通空白材料消耗。
- 存储介质一律从无数据组件新造，使用时按现有身份机制初始化；不复制旧介质 ID，不提供含库存盘的拆解或升级配方。

### 7.2 实施顺序

1. 注册新矿物、材料、基础加工机和发电机，完成普通手工配方与独立供能；新增方块定义仍由 `common/definitions.py` 统一驱动资产生成。
2. 上线 DOS 仓储、现有已注册介质、终端和工具的配方，验证真实生存开局。
3. 使用不消耗带状态成品的独立制作配方，上线样板、自动化与高档布线；只有无状态成品保留升级配方。
4. 八种已明确规格的介质一起注册；流体接口配方不补齐既有未完成的缓冲能力，本稿也不补齐未定义容量。

### 7.3 需要验证的结果

- 清单完整：当前 26 个整方块设备、3 种光缆、4 种终端面板部件、1 种 P2P 部件、1 种底座、4 个工具、1 种样板、8 个介质规格、8 种内存均有配方或明确的无配方说明。
- 配方正确：工作台最多 9 格、无重复输入歧义、产量与批量成本一致；所有非原版消耗品都有可达来源；无材料增殖循环。
- 数据安全：含库存设备、编码样板、配对工具、身份异常介质不能被错误消费；合成与存档重载不复制数据。
- 机器正确：空燃料、掉电、输出满、拆机、跨存档恢复、漏斗和样板投料均保持物料守恒；发电六面合计功率不超标。
- 平衡：记录首个仓储网络的金/铁/水晶消耗、首条自动芯片线耗时、不同存储路线的成本，以及高密磁带首次可获得的阶段。
- 开发验证：代码落地时运行完整兼容性/测试门禁及生成资产 `--check`；配方、机器容器、能源联动另做游戏验证。本文档检查不能替代这些验收。
