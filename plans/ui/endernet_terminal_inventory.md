## 1. 制作范围与要求

自定义真实玩家背包显示与交互：取放、拆分、合并、交换、快捷转移及特殊物品元数据。逐项确认 UI 索引到真实背包／快捷栏槽号的映射；现有模拟背包说明不自动成为真实存取契约。

需求依据：[Task 11](../tasks/11.%20终端与客户端同步.md)、[方块说明](../blocks.md)。具体布局和控件用途由 User 制作后填写；以下空表不是已确认的 UI 约定。

**2026-09-30：槽位映射与操作流程已由 User 裁定**（决策 D1–D4，同时裁定下方背包
接**真实玩家背包**、不再用本地模拟模型）。这一份裁定是口头的、没有走本文档第二节
到第七节的表格，因此下面几节仍是「待填写」——**不要把它读成「这些表已经核过了」**。

**UI 索引 → 引擎槽号**（决策 D2）。`#collection_index` 在**各自集合内**从 0 起，
两段是界面自己的编号，不是引擎槽号：

| 界面区段 | collection | 界面索引 | 引擎槽号 | 说明 |
| --- | --- | --- | --- | --- |
| 上方 9×3（背包） | `endernet_terminal_backpack` | 0–26 | **9–35** | 引擎里 9–35 是背包 27 格 |
| 下方 9×1（快捷栏） | `endernet_terminal_hotbar` | 27–35 | **0–8** | 引擎里 0–8 是快捷栏 |

**引擎的顺序是快捷栏在前、界面是背包在前**，两套槽序正好相反。换算只有一处定义
（`client/ui/backpack_model.py` 的 `engine_slot_of`），改动它必须同步
`endernet_tests/test_backpack_model.py` 的四个端点断言。**写反了不会报错**：客户端
用同一张表同时算出槽号与指纹，服务端的锚只回答「这个槽里是不是这件东西」——自己
和自己必然一致，症状是**搬走玩家没点的那一格**，只有逐格实点才看得出来。

**操作流程**（决策 D1）：点背包槽只**选中**（不搬任何东西；空格子点不动；同格再点
取消），再点一个终端行才交接，方向 `inv_take`（背包 → 网络），数量取那一槽的**一组**
= `min(该槽数量, maxStackSize)`。**没有选中**时点终端行仍是原有的 `inv_put`。
这一条与 `inv_put` 的「取一组」一样，是**本轮定的默认、不是玩法定案**，R12 定稿后
即被取代，详见 [Task 11](../tasks/11.%20终端与客户端同步.md) 文末的补充段。

**背包槽之间的交换与合并**（2026-09-30 补定并接上，**仅离线验证**）：选中之后点**另一个背包槽**
（而不是终端行）时，动作发生在**背包内部**、不经过网络——同种且可合并 → **合并**；
异种 → **交换**；目标为空 → **交换**（与空槽交换即移动）。手势与网络存取**共用同一份
选中态**，所以两条路天然互斥：选中了背包槽再点终端行仍然是 `inv_take`。
**本文件对应的界面现在还没接这一条**：点第二个背包槽只会把选中挪过去。服务端侧
**服务端五个命令已齐**（`inv_merge` 早就有，`inv_swap` 于同日补上，
见 [欠账台账](../tasks/00-欠账台账.md) **S-16**），**界面的这一条也已接**
（`BackpackModel.pending_exchange` → `TerminalListView.on_backpack_exchange`）。
仍未接的是**拆分与快捷转移**：那两个命令早已实现，缺的是属 R12 的手势。
**全部只在离线验证过**——真机没跑。
