## 一、结论

两份 JSON 都已经画出了骨架（`template_terminal_panel.json` 39 个控件、
`factoric_terminal_panel.json` 48 个控件），但**两份交接文档的第 2～7 节
全部是空模板**，按 Task 11「UI 分工与实施前置」（[11. 终端与客户端同步.md:30](11.%20终端与客户端同步.md)）
只能停在第 1 步——**列缺项，不动工**。

静态核实还发现三件与「只是没交接」不同的事，它们决定了不能靠猜开工：

1. **两个界面的按钮事件全是编辑器占位串**（`%netease_editor_template_namespace.click` +
   空 `button_mappings`），与 11 文档第 89 行记录过的现状同形；
2. **样板终端的网络列表根本没接终端绑定字段**（它复用的是引擎集合的普通容器
   grid，不是通用/合成终端那套 `terminal_slot` 模板，见 B3）；
3. **工厂终端的需求里有一半在 JSON 里找不到对应控件**（「提交」「材料缺口」
   「规划预览」「阻塞原因」，见 C1）。

两台方块本身在定义表里早已存在（`common/definitions.py:943` / `:951`，
`CATEGORY_TERMINAL`、带宽 1u、耗能 4 EN/t），但 `TERMINAL_SCREENS`（同文件 `:742`）
**只登记了通用与合成两台**，因此右键这两台今天**不会打开任何界面**，
也不会推身份。登记与写屏都等交接。

## 二、A 组：打开入口与注册（两台共用）

- **A1 两台都走终端那条路**：屏幕由本模组自有、服务端 `PushUIRequest` 推开、
  屏类 `is_proxy=False`——与通用/合成终端同一机制，**不是** 11-07 的容器代理那条。
  要从交接拿到的：屏幕名（JSON 里读到的是 `template_terminal_panel_ui.main` /
  `factoric_terminal_panel_ui.main`，需确认）、打开入口（哪台方块、右键是否即开）。
  **定案前不往 `TERMINAL_SCREENS` 加行**——加了就是替「这个界面从哪开」定案。
- **A2 两台都没有详情弹窗实例。** `grep device_status_window_basic` 全仓命中 6 个
  文件（`endernet_windows.json` + 通用终端 + 四台容器设备），**不含这两台**。
  11-13 要求「点 `stat_bar` 的 `interact_btn` 打开 `device_status_window_basic`」，
  缺这一条实例。
  **顺带：`crafting_terminal_panel.json` 同样没有**（同一次 grep）。它属已交付的
  11-04，一并交给 User 判断要不要补。
- **A3 遮罩不齐**：样板终端有 `unavailable_mask`（`template_terminal_panel.json:510`）
  但**没有任何绑定**；工厂终端**根本没有遮罩控件**。通用终端那份的写法是
  `#EnderNetTerminal.unavailable -> #visible(always){global}`，两台要对齐。

## 五、D 组：服务端与协议缺口（脚本侧，但依赖交接口径）

- **D1 两条命令不存在。** `server/storage/service.py:1361` 的 handlers 表共 22 项，
  没有样板编码/更新，也没有订单提交/取消。领域层**都已经有了**：
  07 的 `encode_pattern` / `decode_pattern`（`crafting/patterns.py:726` / `:743`）、
  09 的 `executor.submit_order` / `cancel`（`crafting/executor.py:295` / `:871`）、
  08 的 `plan`（`crafting/planner.py:2983`）。缺的是**命令层与消息形状**。
- **D2 现有 `TerminalCommand` 够不够，取决于交互约定。** 它的字段是
  `request_id` / `expected_index_version` / `action` / `key` / `count` / `slot` /
  `slot_version` / `into_slot`：样板要「输入列表 + 多产物 + 模式」三份数据，
  订单要「目标 + 数量」（还要定一次提交一个还是批量）。按任务文档第 30 / 35 行，
  **依赖该 UI 交互约定的协议也必须暂停**——所以不在交接前设计。
- **D3「规划预览不表示资源已锁定」需要一条只读通道。** 预览不能用会真的下单的
  动作来实现；这一条的形态（复用 `command_result` 还是新消息）等 C1 的控件定下来
  再说。
