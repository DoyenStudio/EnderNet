# 06. 资源转移与自动输入输出服务

状态：未开始。负责人：待分配。前置：03—05、13-01 的容器契约；真实流体路径依赖 13-03；缓冲与操作恢复契约提前对接 12。

## 目标与边界

统一搬运网络与外部容器间的资源，实现总线接口、存货口和取货口。样板接口的投料也复用同一转移机制，避免另写一套扣库存逻辑。

代码归属：`ROOT/server/storage/transfer.py`、`server/devices/io.py`、`server/adapters/containers.py`。参考 AE2 的统一网络存取入口；网易容器操作的提交细节按实际 API 验证。

## 接口与交付

`TransferRequest` 包含来源、目标、资源、数量、操作 ID、主控/拓扑版本和可选预留凭据；`TransferReceipt` 返回实际量、余量、当前持有者和状态。缓冲有明确容量、拥有者和保存结构；外部容器适配契约由 13 定义。

玩家背包作为实际转移端点，使用玩家、槽号、槽版本和物品指纹定位，不能以客户端显示索引代替。网络虚拟槽数量可以很大；写入真实背包时按物品 maxStackSize、可合并性、可用槽和介质预算拆分或部分接受，保留所有元数据。

## 分步任务

- [ ] 06-01 实现无副作用预检和受控提交阶段，统一检查库存、空间、速率、能源、节点代次及主控状态。
- [ ] 06-02 实现实际数量回执，覆盖全成功、部分成功、拒绝和结果不确定。结果不确定不能作为成功，也不能盲目重试。
- [ ] 06-03 实现有界中转缓冲和资源归属转移；失败时可确认剩余资源的位置，避免先删源再假定目标接收。
- [ ] 06-04 实现被动总线物品/流体接口：外部物流访问本地缓冲，按配置与网络交换；将外部写入和本模组内部移动区分，避免反复导入导出计作新回流。
- [ ] 06-05 实现存货口：读取朝向容器的可提取内容，向主控请求存入；网络拒收部分留在可追踪位置。
- [ ] 06-06 实现取货口：按过滤和需求从网络请求资源，向朝向容器供给；无空间时退避，不丢弃余量或超量输出。
- [ ] 06-07 为样板接口提供成批备料/投料入口和本地缓冲回执。外部机器部分接收时保留批次状态，交由 09 决定后续推进。
- [ ] 06-08 接入事件唤醒、低频轮询、配置变化和卸载取消；提交后分别通知 05 的库存视图和 10 的合格回流入口。
- [ ] 06-09 提供自定义背包槽需要的取放、拆分、合并和快捷转移命令，和 11-12 对接；校验背包并发变动，处理有限持有物及 R12 的退出规则，重复请求只生效一次。

## 验收

- [ ] 满容器、缺物品、写入失败、目标卸载、方向改变和部分写入时，资源守恒且不会无限忙轮询。
- [ ] 主控无效或断电不继续抽取源容器；外部物流已送入缓冲的资源仍保留。
- [ ] 取货口与存货口同时操作同一容器不会重复扣取；同一个转移重试不会完成两次。
- [ ] 普通库存搬迁、补偿和恢复不新增订单产物计数；真实新输入只发一份回执。
- [ ] 当前 ToolDelta 高层插入方法的失败路径单独验证，不能仅凭“无余量”推断引擎写入成功。
- [ ] 大于 maxStackSize 的网络提取不会生成超堆叠背包物品；背包容量不足只转移实际数量；背包槽在点击后变更时不会误取替换后的物品。

## 待定与交接

R05 决定缓冲容量、写盘阻塞及余料处置。外部 API 不保证事务时，只对已确认操作给出守恒承诺；无法确认的崩溃窗口由 12 记录和恢复，不承诺任意外部模组的精确一次提交。
