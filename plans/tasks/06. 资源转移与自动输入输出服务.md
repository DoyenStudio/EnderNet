## 目标与边界

统一搬运网络与外部容器间的资源，实现总线接口、存货口和取货口。样板接口的投料也复用同一转移机制，避免另写一套扣库存逻辑。

代码归属：`ROOT/server/storage/transfer.py`、`server/devices/io.py`、`server/adapters/containers.py`（纯契约与测试替身）及 `server/adapters/containers_engine.py`（真实引擎实现）。存储驱动器的介质装卸也复用转移机制，归属与接线见 [设备脚本架构](../technical_notes/script_architecture.md)。参考 AE2 的统一网络存取入口；网易容器操作的提交细节按实际 API 验证。

## 验收

- [ ] 满容器、缺物品、写入失败、目标卸载、方向改变和部分写入时，资源守恒且不会无限忙轮询。
- [ ] 主控无效或断电不继续抽取源容器；外部物流已送入缓冲的资源仍保留。
- [ ] 取货口与存货口同时操作同一容器不会重复扣取；同一个转移重试不会完成两次。
- [ ] 普通库存搬迁、补偿和恢复不新增订单产物计数；真实新输入只发一份回执。
- [ ] 当前 ToolDelta 高层插入方法的失败路径单独验证，不能仅凭“无余量”推断引擎写入成功。
- [ ] 大于 maxStackSize 的网络提取不会生成超堆叠背包物品；背包容量不足只转移实际数量；背包槽在点击后变更时不会误取替换后的物品。

## 待定与交接

介质 Lore 写回按 [刷新与交接契约](../technical_notes/medium_lore.md#5-写回与交接顺序)：普通展示刷新合并、限预算、失败退避；真实交接捕获并核对介质 ID、槽位/设备代次与内容版本，将最新两行合入交接载荷。不得先交出旧物品再按旧槽号补写，也不得把仅展示更新当作资源转移或回流。实际失败/不确定结果沿用现有回执与核对机制。
