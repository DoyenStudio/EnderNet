# 11. 终端与客户端同步

状态：未开始。负责人：待分配。前置：01、03、05；基础终端先实现，合成/样板终端接 07，工厂终端接 08—10。

## 目标与边界

实现通用、合成、样板、工厂四类终端及设备配置交互。客户端只维护显示缓存和交互状态，服务端验证并执行命令，不能由客户端提交库存余额或“订单已完成”。

界面参考 AE2 面板，必须自行实现动态网络物品长列表的槽位逻辑，以及本界面内玩家背包槽的渲染与交互。网络汇总数量可超过 `maxStackSize`；真实玩家背包堆叠仍受游戏上限约束。接网设备除控制器本身外，在 `stat_bar` 显示绿色“在线”或红色“离线”，点击 `interact_btn` 弹出 `device_status_window_basic` 查看详情。

代码归属：`ROOT/server/sync/`、`common/protocol.py`、`client/network_client.py`、`client/ui/`。按 [设备脚本架构](../technical_notes/script_architecture.md) 统一沿用已有 `client/ui/`，显示模型放 `inventory_model.py` / `item_list_model.py`，共用组件放 `ui/widgets/`，不再并列建立 screens、slots、render 或 view_models。UI JSON、纹理及本地化位于资源包对应目录，绑定名与脚本共同维护。

## UI 分工与实施前置

11-06 的已确认显示需求：订单执行进度为已完成配方任务数／订单树配方任务总数，同配方执行 10 次计 10 个任务；网络运行内存以字节（B）表示。服务端数据须遵守 [订单规则](../technical_notes/order_planning_execution.md)，执行期间随完成事件更新。这里只记录需求，不指定控件或交互方式；相关 UI 未交接时必须暂停 UI 逻辑及依赖其约定的同步对接。

**界面创建由 User 全权完成。** 所有设备与终端的 UI，包括物品槽位、过滤配置格、按钮、开关、状态栏、弹窗及其他控件的创建、布局和视觉资源，均由 User 负责。本文各步骤中的“实现界面／槽位／控件”须按此分工执行，不授权脚本实现方（Codex）自行创建这些 UI。

实施顺序按每个界面分别执行：

1. 脚本实现方仅根据已确认的需求列出 UI 缺项，缺失界面或控件交由 User 创建，并记录“等待 User 创建 UI”。一旦工作涉及缺失 UI 的逻辑，必须暂停这部分工作，不能假设任何 UI 逻辑，包括控件结构、槽位映射、按钮／开关行为、事件、绑定、交互流程及其同步约定；不得用占位、模拟逻辑或“先写脚本后适配”绕过此前置条件。已有 UI JSON 或占位控件不自动代表 User 已完成交接。
2. User 完成相应界面后交接资源文件、控件路径及用途；脚本实现方核对真实槽、虚拟配置格、按钮和开关的含义，再开始该界面的脚本对接。
3. 脚本实现方对接屏幕注册与打开入口、绑定、事件、数据同步和服务端命令，并可按对接需要微调现有 UI，例如绑定字段、控件路径适配、尺寸、间距和文字显示。新增控件、补建界面或整体布局重做仍由 User 完成，不能作为“微调”自行代做。
4. 对接后验证实际打开、交互、同步及移动端显示，分别记录 User 的 UI 创建交付与脚本接入／游戏验证进度。

此约定覆盖 11-03 至 11-07 的终端与设备配置，以及 11-10、11-12、11-13 的槽位显示、背包和状态控件。动态列表的控件池与运行时复用使用 User 已交付的槽位模板，脚本负责数据和交互逻辑。等待 UI 期间，仅可继续完全不依赖该 UI、无需假设其行为的独立工作；服务端、协议和数据模型若依赖该 UI 的交互约定，也必须暂停。User 完成相应 UI 并交接、相关逻辑依据明确后，才能恢复这部分工作；等待期间不能把相应界面标为完成。

## 接口与交付

会话绑定玩家、终端位置/代次、网络/主控实例；请求含请求 ID、动作和期望版本，服务端从可信事件取得玩家身份。同步区分快照、增量、确认与错误；增量包含基准和结果版本。

新增交付：`client/ui/` 的网络槽与背包槽模型和交互状态机，`client/ui/widgets/` 的共用槽位显示、虚拟滚动列表与设备状态面板，`server/sync/device_status.py` 的状态聚合与订阅。`sync/sessions.py` 负责共用会话校验，`sync/devices.py` 负责驱动器槽位／配置同步，`sync/terminal.py` 负责库存快照与增量。这里的自定义槽位可以调用现有引擎物品图标渲染能力；业务去重复用主控账本。

## 自定义槽位与长列表契约

| 模型 | 身份与数量 | 行为边界 |
| --- | --- | --- |
| 网络槽 | `ResourceKey`，总量/预留/可用量，无固定列表长度 | 大数量独立绘制，不受图标样本 `maxStackSize` 截断 |
| 玩家背包槽 | 玩家、真实槽号、槽版本与物品指纹 | 自定义显示与交互，但实际取放、拆分、合并受堆叠上限约束 |
| 合成/样板槽 | 明确的槽位用途及其索引 | 实物合成格与虚拟配方配置格分开，禁止配置项变成真实物品 |

列表使用可见行与少量缓冲行的控件池，逻辑数据独立于控件。分页/分批是传输策略，控件复用是渲染策略，二者都要实现。以稳定资源键保存选中项，列表插入、删除、排序时校正滚动锚点；查询响应附查询代次与版本，旧响应不能覆盖新搜索结果。

数量标签支持紧凑显示，详细提示保留精确整数；交互不得解析“1.2K”等显示文字作为提交数量。请求描述来源、目标、动作和数量，携带资源键或真实背包槽身份，服务端校验后经主控与转移服务执行。排队中的点击保留原目标身份，不能在控件复用后重新读取当前显示物品。

交互范围包括取放、拆分、合并、快捷转移及触控对应操作；拖拽、长按、鼠标键位/组合键等映射由 R12 定稿。客户端光标和选中效果只是表现；若有真实持有物，服务端须记录唯一归属，并处理关闭界面、断线、死亡、背包满和重连。成功前不凭本地动画完成资源转移。

## 设备总体状态与详情弹窗契约

### 接口配置界面补充（11-07，待实现与验收）

被动接口显示存取共用的 9 个真实槽位和最多 9 种取货配置；主动取货口只显示最多 9 种资源配置，不提供内部库存槽；主动存货口提供黑白名单模式与过滤条目；样板接口显示 9 个工厂样板实物槽，原料缓冲另行显示，不混用槽号或数据源。

资源配置格是虚拟条目，设置/清除不消耗或生成物品；样板槽和被动库存槽是真实资源，取放必须经过服务端交接。配置命令带设备代次、请求 ID 和期望配置版本，服务端校验资源身份、允许类型及已确定的 9 种取货上限，处理多人同时编辑和过期响应。黑白名单默认模式、空名单行为、过滤条目上限及共享槽分工尚待确认，UI 不自行决定规则；配置改变后的余料处置与 06/12 统一。

验收补充：非法第 10 种取货配置被服务端拒绝；虚拟配置与真实槽取放不混淆；黑白名单切换按最终规则生效；断线重连和设备替换后不应用旧配置。

### 总体状态与详情

- 适用对象是非控制器的接网设备；“网络控制器”分组下的所有型号都排除，不自动套用此状态栏与详情流程。现有设备界面复用 `stat_bar`，后续设备界面也按此统一接入。
- `stat_bar/stat_text` 只显示“在线”（绿色）或“离线”（红色），不再并列显示能源/带宽 OK，也不保留黄色“未知状态”作为正式第三态。颜色建议使用 `(0,1,0)` 与 `(1,0,0)`，由颜色绑定与文本同步更新。
- 在线是服务端对本设备总体工作条件的确认：有效唯一主控、控制器支持该设备、网络允许工作、能源满足、负载获准。有效性缺失、过期、恢复/重建中均显示离线，具体原因留在详情。设备空闲或当前没有可搬运物品不算离线。
- `DeviceNetworkStatus` 携带 `is_online`、有效性、设备代次、主控身份、负载域、状态版本和详细原因。能源与带宽仍独立计算；恰好满载是否影响准入仍按 R13 策略，状态栏不另算一套。
- 点击 `stat_bar/interact_btn` 后，显示 `endernet_windows.device_status_window_basic`。复用现有 `controller_conn_stat` 行呈现控制器连接/冲突/支持情况，`network_conn_stat` 行呈现总体网络情况和能源、带宽、重建等具体原因；多个原因不能只显示静态“网络故障中”。根据所需行数调整布局，避免 128×64 初始尺寸截断详情。
- 弹窗是已有 panel 的界面实例，不把空的 `endernet_windows.main` 误认为已经可用的详情页面。采用设备界面内弹窗层时，初始隐藏、置顶显示、阻止点击穿透；点击关闭只隐藏详情，不关闭原设备界面。
- 同设备连点只显示一个弹窗；断电、超载、无主控时按钮仍可用。只读诊断校验玩家、维度、距离和设备实例，但不要求设备先在线。
- 打开时读取当前快照并继续更新；切换设备、设备替换、主界面关闭或玩家离开时关闭弹窗并清理订阅。旧设备响应不能更新新设备的状态栏或弹窗。

## ToolDelta 绑定实施约定

在注册的 `ToolDeltaScreen` 子类上使用 `tooldelta.ui.Binder` 静态绑定；状态栏为单实例控件，使用普通绑定，不因模板包含空的 collection 标记就使用集合绑定。JSON 名称与 Python 名称必须一致且保留 `#` 前缀。

建议新增以下业务绑定名（目前尚未实现）：`#EnderNetDeviceStatus.text` 配 `BF_BindString`、`.color` 配 `BF_BindColor`、`.visible` 配 `BF_BindBool`、`.open`/`.close` 配确定的按钮事件。实现时同步配置 JSON 的实际绑定、`$pressed_button_name` 和 `button_mappings`；按目标环境确认按下/抬起只触发一次。内部图标、详情行文本及遮罩同样绑定到当前快照，不能保留静态占位错误图标。
