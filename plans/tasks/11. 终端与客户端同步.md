# 11. 终端与客户端同步

状态：未开始。负责人：待分配。前置：01、03、05；基础终端先实现，合成/样板终端接 07，工厂终端接 08—10。

## 目标与边界

实现通用、合成、样板、工厂四类终端及设备配置交互。客户端只维护显示缓存和交互状态，服务端验证并执行命令，不能由客户端提交库存余额或“订单已完成”。

界面参考 AE2 面板，必须自行实现动态网络物品长列表的槽位逻辑，以及本界面内玩家背包槽的渲染与交互。网络汇总数量可超过 `maxStackSize`；真实玩家背包堆叠仍受游戏上限约束。所有接网设备的界面都显示本设备能源、带宽两项独立状态。

代码归属：`ROOT/server/sync/`、`common/protocol.py`、`client/{network_client,view_models}.py`、`client/screens/`、`client/render/`。UI JSON、纹理及本地化位于资源包对应目录，绑定名与脚本共同维护。

## 接口与交付

会话绑定玩家、终端位置/代次、网络/主控实例；请求含请求 ID、动作和期望版本，服务端从可信事件取得玩家身份。同步区分快照、增量、确认与错误；增量包含基准和结果版本。

新增交付：`client/slots/` 的网络槽与背包槽模型、渲染器和交互状态机，`client/widgets/` 的虚拟滚动列表、数量标签与设备状态面板，`server/sync/device_status.py` 的状态聚合与订阅。这里的自定义槽位负责业务语义与交互，可以调用现有引擎物品图标渲染能力。

## 自定义槽位与长列表契约

| 模型 | 身份与数量 | 行为边界 |
| --- | --- | --- |
| 网络槽 | `ResourceKey`，总量/预留/可用量，无固定列表长度 | 大数量独立绘制，不受图标样本 `maxStackSize` 截断 |
| 玩家背包槽 | 玩家、真实槽号、槽版本与物品指纹 | 自定义显示与交互，但实际取放、拆分、合并受堆叠上限约束 |
| 合成/样板槽 | 明确的槽位用途及其索引 | 实物合成格与虚拟配方配置格分开，禁止配置项变成真实物品 |

列表使用可见行与少量缓冲行的控件池，逻辑数据独立于控件。分页/分批是传输策略，控件复用是渲染策略，二者都要实现。以稳定资源键保存选中项，列表插入、删除、排序时校正滚动锚点；查询响应附查询代次与版本，旧响应不能覆盖新搜索结果。

数量标签支持紧凑显示，详细提示保留精确整数；交互不得解析“1.2K”等显示文字作为提交数量。请求描述来源、目标、动作和数量，携带资源键或真实背包槽身份，服务端校验后经主控与转移服务执行。排队中的点击保留原目标身份，不能在控件复用后重新读取当前显示物品。

交互范围包括取放、拆分、合并、快捷转移及触控对应操作；拖拽、长按、鼠标键位/组合键等映射由 R12 定稿。客户端光标和选中效果只是表现；若有真实持有物，服务端须记录唯一归属，并处理关闭界面、断线、死亡、背包满和重连。成功前不凭本地动画完成资源转移。

## 设备入网状态契约

- 固定显示“能源 OK？”与“带宽 OK？”两项，不用一个总在线状态替代。面向所有接网设备界面；无独立操作界面的设备提供共用状态面板。
- `power_ok` 来自能源服务，`bandwidth_ok` 来自本设备所属负载域的准入结果。控制器分别连接的独立基带分别计算，不能显示另一个分支的剩余额度。
- 按建议口径，已获分配且恰好满载的设备带宽仍为 OK；无法获准的新设备为未满足。可附需求/已用/容量数字；R13 定稿文案与满载边界。
- 两项状态分别带有效性和原因，快照含设备代次、主控身份、负载域及状态版本。等待快照、拓扑重建或状态失效时显示“—/待确认”，不是第三个业务检查项。
- 只读诊断不要求设备业务准入成功，断电、超载、无主控时仍可打开看原因；校验玩家和设备身份仍必需。关闭界面解除订阅。
- 能源失败不推导带宽失败，带宽失败不推导能源失败。主控型号不支持某动作等另列说明，两项均 OK 不允许绕过服务端命令校验。

## 验收

- [ ] 两玩家同时存取、重发请求、关闭重开界面时，显示最终与服务端一致且不重复提交。
- [ ] 伪造身份、远程已失效终端、负数量、非法资源及过期版本请求被拒绝。
- [ ] 快照期间发生增量、增量丢失/重复/乱序时，可按版本恢复；不依赖客户端预测数量。
- [ ] 四类终端分别完成其独立用途；合成终端实际合成消耗网络材料，不只显示配方。
- [ ] 通用输入输出接口可以在游戏中配置；窗口关闭后没有持续的全网库存推送。
- [ ] 移动端尺寸、长物品名、大数量、流体单位和本地化均能正确显示。
- [ ] 列表在 0、1、超过一屏及大规模资源种类下可正确滚动和筛选；控件数由可视区域决定，不随全部条目数线性创建。
- [ ] 同种物品显示 1、maxStackSize、maxStackSize+1、2^30 等数量时精确保留库存；取到真实背包的每个堆叠仍不超过上限，背包满时只转移实际可接收量。
- [ ] 快速滚动、排序和收到增量后点击，不会误取旧控件或新占位物品；重复点击与超时重试不重复扣库存。
- [ ] 自定义背包拆分、合并、快捷转移和特殊物品交互与服务端真实槽一致；关闭/断线后无遗失或复制的持有物。
- [ ] 分别验证能源 OK/不足与带宽 OK/不足的组合、恰好满载、不同负载域；任一项变化不会错误覆盖另一项。
- [ ] 设备断电或超载后仍可查看状态，重建期间不显示旧绿色结果；控制器型号不支持的功能不会因两项 OK 被错误启用。
