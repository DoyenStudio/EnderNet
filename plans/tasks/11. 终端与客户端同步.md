## 接口与交付

会话绑定玩家、终端位置/代次、网络/主控实例；请求含请求 ID、动作和期望版本，服务端从可信事件取得玩家身份。同步区分快照、增量、确认与错误；增量包含基准和结果版本。

**命令通道已由 11-03 定稿**（线格式见 `common/protocol.py`，实施细则见 [终端物品索引](../technical_notes/terminal_item_index.md) §7）：

| 项 | 定稿 |
| --- | --- |
| 消息种类 | C2S `command`（`TerminalCommand`）／S2C `command_result`（`CommandResultMessage`） |
| `TerminalCommand` 字段 | `request_id`、`expected_index_version`、`action`、`key`、`count`、`slot`、`slot_version`、`into_slot`；**全部无条件序列化、缺席写 `None`**，因此缺字段与多字段都会被协议层拒绝 |
| 来源与目标 | **不在消息里**。玩家取 `session.player_id`、终端取 `session.device_ref`、维度取 `session.dimension`——会话已经结构性给出，再带一份就是第二个真相源并给伪造留口子 |
| 期望版本 | `expected_index_version` 对的是**交易预期版本**（`StorageService.index_version`），**不是**物品视图发布版本 `item_view_version`；两者各有其名，不能互相顶替 |
| 服务端 | `TerminalSyncHub._on_command` 构造 `CommandSource` 后交给注入的 `submit`；`topology_version=None` 是有意的（hub 没有权威图版本源，映射过去就是把两个版本混成一个） |
| 回执 | `CommandResult.to_dict()` 原样字典；协议层只验形状，**不重建领域对象**（`CommandResult` / `TransferReceipt` 都没有 `from_dict`） |
| 执行 | 复用 `StorageService.handle` 已有的五个背包动作，**没有新增动作语义**（说的是**通道层不发明动作**；动作集合本身后来变了——2026-09-30 补定「交换」，服务端尚缺该命令，见文末补充段与 [欠账台账](./00-欠账台账.md) D-07） |
| 确认 | 只 ack 增量（`transfer_id = batch_id`，`sequence` = 最大连续 `packet_index`）；**快照块永远不 ack**——服务端发它们时不带 transfer_id |

**`cursor` 字段不发**：`_cursor_refusal` 只在 `payload.get("cursor")` 为真时才拒，
因此不发等于**没有这只手**，不等于客户端声称「手上没东西」。这是**缺席**，
不是定案——见下方「待定与交接」。

新增交付：`client/ui/` 的网络槽与背包槽模型和交互状态机，`client/ui/widgets/` 的共用槽位显示、虚拟滚动列表与设备状态面板，`server/sync/device_status.py` 的状态聚合与订阅。`sync/sessions.py` 负责共用会话校验，`sync/devices.py` 负责驱动器槽位／配置同步，`sync/terminal.py` 负责库存快照与增量。这里的自定义槽位可以调用现有引擎物品图标渲染能力；业务去重复用主控账本。

## 自定义槽位与长列表契约

| 模型 | 身份与数量 | 行为边界 |
| --- | --- | --- |
| 网络槽 | `ResourceKey`，总量/预留/可用量，无固定列表长度 | 大数量独立绘制，不受图标样本 `maxStackSize` 截断 |
| 玩家背包槽 | 玩家、真实槽号、槽版本与物品指纹 | 自定义显示与交互，但实际取放、拆分、合并、交换受堆叠上限约束 |
| 合成/样板槽 | 明确的槽位用途及其索引 | 实物合成格与虚拟配方配置格分开，禁止配置项变成真实物品 |

列表使用可见行与少量缓冲行的控件池，逻辑数据独立于控件。分页/分批是传输策略，控件复用是渲染策略，二者都要实现。以稳定资源键保存选中项，列表插入、删除、排序时校正滚动锚点；查询响应附查询代次与版本，旧响应不能覆盖新搜索结果。

数量标签支持紧凑显示，详细提示保留精确整数；交互不得解析“1.2K”等显示文字作为提交数量。请求描述来源、目标、动作和数量，携带资源键或真实背包槽身份，服务端校验后经主控与转移服务执行。排队中的点击保留原目标身份，不能在控件复用后重新读取当前显示物品。

交互范围包括取放、拆分、合并、交换、快捷转移及触控对应操作；拖拽、长按、鼠标键位/组合键等映射由 R12 定稿——其中**「点选中 → 再点目标」这一条已于 2026-09-30 定案**（见文末补充段），它不产生持有物，因此下面这句的持有物归属仍属未定部分。客户端光标和选中效果只是表现；若有真实持有物，服务端须记录唯一归属，并处理关闭界面、断线、死亡、背包满和重连。成功前不凭本地动画完成资源转移。

**背包槽之间的操作不经过网络。** 拆分、合并与交换只在玩家背包内部发生，与「网络 ↔ 背包」的取放是两类动作：前者不改变网络库存，后者才走转移服务与去重账本。两类都由服务端执行（客户端只发命令、不本地写入），都校验两端的槽号、物品指纹与槽版本。

### 总体状态与详情

- 适用对象是非控制器的接网设备；“网络控制器”分组下的所有型号都排除，不自动套用此状态栏与详情流程。现有设备界面复用 `stat_bar`，后续设备界面也按此统一接入。
- `stat_bar/stat_text` 只显示“在线”（绿色）或“离线”（红色），不再并列显示能源/带宽 OK，也不保留黄色“未知状态”作为正式第三态。颜色建议使用 `(0,1,0)` 与 `(1,0,0)`，由颜色绑定与文本同步更新。
- 在线是服务端对本设备总体工作条件的确认：有效唯一主控、控制器支持该设备、网络允许工作、能源满足、负载获准。有效性缺失、过期、恢复/重建中均显示离线，具体原因留在详情。设备空闲或当前没有可搬运物品不算离线。
- `DeviceNetworkStatus` 携带 `is_online`、有效性、设备代次、主控身份、负载域、状态版本和详细原因。能源与带宽仍独立计算；恰好满载是否影响准入仍按 R13 策略，状态栏不另算一套。
- 点击 `stat_bar/interact_btn` 后，显示 `endernet_windows.device_status_window_basic`。复用现有 `controller_conn_stat` 行呈现控制器连接/冲突/支持情况，`network_conn_stat` 行呈现总体网络情况和能源、带宽、重建等具体原因；多个原因不能只显示静态“网络故障中”。根据所需行数调整布局，避免 128×64 初始尺寸截断详情。
- 弹窗是已有 panel 的界面实例，不把空的 `endernet_windows.main` 误认为已经可用的详情页面。采用设备界面内弹窗层时，初始隐藏、置顶显示、阻止点击穿透；点击关闭只隐藏详情，不关闭原设备界面。
- 同设备连点只显示一个弹窗；断电、超载、无主控时按钮仍可用。只读诊断校验玩家、维度、距离和设备实例，但不要求设备先在线。
- 打开时读取当前快照并继续更新；切换设备、设备替换、主界面关闭或玩家离开时关闭弹窗并清理订阅。旧设备响应不能更新新设备的状态栏或弹窗。

## ToolDelta 绑定实施约定

在注册的 `ToolDeltaScreen` 子类上使用 `tooldelta.ui.Binder` 静态绑定；状态栏为单实例控件，使用普通绑定，不因模板包含空的 collection 标记就使用集合绑定。JSON 名称与 Python 名称必须一致且保留 `#` 前缀。

建议新增以下业务绑定名（目前尚未实现）：`#EnderNetDeviceStatus.text` 配 `BF_BindString`、`.color` 配 `BF_BindColor`、`.visible` 配 `BF_BindBool`、`.open`/`.close` 配确定的按钮事件。实现时同步配置 JSON 的实际绑定、`$pressed_button_name` 和 `button_mappings`；按目标环境确认按下/抬起只触发一次。内部图标、详情行文本及遮罩同样绑定到当前快照，不能保留静态占位错误图标。

**2026-10-01 关于空闲会话回收的补充**：第十五节（[交付说明](11-交付说明.md)）
真机实测发现「终端开着不动 20 秒，会话被服务端回收且**一条包都不发**，
界面继续显示过期库存，点下去才失效」。**已按当时的第一个候选修掉**——
服务端在回收那一刻主动推一条**空 `session_id`** 的 `error`，客户端零改动
就能丢会话、亮遮罩；欠账台账补记 **D-08**。三条口径要说清楚，免得读成
「会话不会掉了」：

> **会话照样会被回收。** TTL（`session.session_ttl_frames`，出厂 600 帧）
> 一个字没改——它是客户端崩溃或断线时的兜底，而客户端**没有 keepalive**，
> 所以「开着但没说话」与「已经不在」在服务端看来本来就是同一件事。变的
> 只是它不再**无声无息**。

- **两条守卫**：①同一玩家的多条会话同帧到期只发一条；②**这个玩家还有
  别的活会话时一条都不发**。第二条是必需的——客户端手里那个会话一定是
  **最后开的**那个（旧的是关界面时那条 `session_close` 没送到才留下的），
  替旧会话发「你的会话没了」，客户端会把它手里那个新的**一起丢掉**。
- **不能用 `_send` 发这一条**：那条路会盖上 `session_id`，而客户端正是靠
  「信封里没有会话号」才认出「这不是某一次请求失败」。带上号等于没发。
- **面板仍然不自救**：会起遮罩，但不会自己重开会话，玩家仍需关掉重开。
  要不要自动重开是一次新决定，本轮**没有替它定案**。
- **另外两条同类的静默注销路径**（设备被替换 `_drop_stale_devices`、
  网络换代次 `on_runtime_change`）~~本轮没接~~ **2026-10-01 同日已接上**：
  与超时那条**共用** `_notify_gone`（两条守卫一字未改），四种注销各带
  各的中文说明，新增 `gone_notices` / `gone_notices_skipped` 两只计数桶；
  客户端与协议**零改动**。**但三条路径一条都没上机**——上面那段真机
  结论只覆盖超时那一条，不顺延。见
  [11-交付说明](11-交付说明.md) 第十八节与 [欠账台账](00-欠账台账.md) **D-08**
  （那里还留着「面板不自救」与一条知情的守卫缺口，D-08 仍未还清）。
- **2026-10-01 已游戏内实测通过**（整包重载后走真实入口开会话，之后什么都
  不做）：服务端 `expired: 1` / `expired_notices: 1`（`skipped: 0`、

**2026-10-01 关于搬运动画落点的补充（User 裁定）**：`content.flying_item` 的
落点此前按「矩形左上角」算，依据是一句「图标与槽位同尺寸」——而那句话是错的：
**槽位面板 18×18，槽里那张图标 16×16 且在槽位里居中**（
[custom_slot 说明](../technical_notes/custom_slot.md) 第 1 节原文如此），两者差
`(18 - 16) / 2 = 1` 像素。User 定「**按 16×16 权威算**」，规则随之改成「把
16×16 的图标摆到目标矩形的**正中**」：槽位内缩 1；背包那一半与列表区这类
**整块区域**落在中心（此前落在左上角，与文档写的「落到列表区中心」是两回事）；
**点击处那条退化矩形原样用那一点**（比图标还小的矩形一律不动）。尺寸只认
`flying_item.ICON_SIZE` 一份，JSON 契约用例把它与两份槽位模板一起钉住——原先
那条恒红的契约断言（拿飞行图标去比槽位**面板**）同日一并改掉。
新增了模块级常量，**必须整包重载**才生效（热重载不换 `func_globals`）；整包
重载后在运行实例上核对了三个分支，**用户随后目测动画并回报「很准确」**。
**但没有逐向确认**：本轮没把三种搬运各驱动一遍，「三种搬运各画一次且方向
正确」那条验收仍不勾。见 [11-交付说明](11-交付说明.md) 第十七节。
