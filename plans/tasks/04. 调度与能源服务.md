# 04. 调度与能源服务

状态：未开始。负责人：待分配。前置：01、03 的事件与服务契约；真实 RF 接入依赖 13-02。

## 目标与边界

建立统一逻辑时钟、多个网络的公平预算、网络内设备到期队列和 EN 供用能管理。调度器决定何时推进，主控制器决定是否允许执行；并行槽位不是 Python 线程。

代码归属：`ROOT/server/runtime/scheduler.py`、`server/network/{ticking,energy}.py`。参考 AE2：`me/service/TickManagerService.java`、`me/service/EnergyService.java`。

## 接口与交付

提供 `schedule/cancel/wake/sleep`、逻辑时间与执行预算、网络能源快照以及能源预留/提交/释放接口。设备耗能来自定义表；介质读写额度由 05 持有，不能在这里复制额度。

为设备界面提供独立的 `power_ok`、判定有效性、原因和状态版本，表示当前供能策略是否满足该设备的能源条件，不用设备综合在线状态代替能源判定。界面读状态不预留、不消耗能源，不能由于没有新的 IO 事务而失去能源状态更新。

- [ ] 04-01 在目标环境核实所选 tick 事件、频率及暂停行为；按 R08 统一 EN/t、每秒吞吐、超时和补偿策略。
- [ ] 04-02 实现到期队列、任务代次与取消；空闲设备睡眠，变化事件唤醒，外部无通知容器使用低频退避轮询。
- [ ] 04-03 加入全局预算与网络轮转，拓扑、规划和 IO 均有限步推进；大网络不能长期饿死小网络。
- [ ] 04-04 根据方块定义结算控制器、驱动器、接口、终端、内存、处理器和装配仓耗能，区分空闲/工作状态；未列数值归入 R10。
- [ ] 04-05 实现 RF 接入后的 EN 计量与必要的有界缓存。自身可控操作按实际消耗结算；外部能源 API 的失败和部分成功通过适配器回执处理。
- [ ] 04-06 断电暂停新业务，取消失效到期任务；恢复后按预算逐步唤醒，不集中补做无限历史 tick。
- [ ] 04-07 记录队列长度、延期次数、执行时长、网络耗能和睡眠比例，向 14 提供可测指标。
- [ ] 04-08 实现本设备能源状态查询与变化通知，接入 11-13；供电、需求或设备工作态变化时更新，拓扑未恢复时标注待确认，带宽不足不自动判成能源不足。

## 验收

- [ ] 同一任务重排不会重复执行；设备替换、卸载后旧任务失效。
- [ ] 空闲网络不高频扫描设备；有变化可唤醒，无事件容器可最终被轮询发现。
- [ ] 假时钟可精确重现低速累积、卡顿和恢复；实际游戏时钟口径另有验证记录。
- [ ] 断电不新抽取原料或凭空完成配方；能源恢复后不重复扣费。
- [ ] 多网络同时繁忙时都有进展，单次推进不无界处理积压任务。
- [ ] 设备界面的能源判定与能源服务一致，读取无副作用；能源不足和带宽不足可以独立显示，断电后仍能获取诊断结果。
