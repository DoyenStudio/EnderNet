## 目标与边界

建立统一逻辑时钟、多个网络的公平预算、网络内设备到期队列和 EN 供用能管理。调度器决定何时推进，主控制器决定是否允许执行；并行槽位不是 Python 线程。

代码归属：`ROOT/server/runtime/scheduler.py`、`server/network/{ticking,energy}.py`。参考 AE2：`me/service/TickManagerService.java`、`me/service/EnergyService.java`。

## 接口与交付

提供 `schedule/cancel/wake/sleep`、逻辑时间与执行预算、网络能源快照以及能源预留/提交/释放接口。设备耗能来自定义表；介质读写额度由 05 持有，不能在这里复制额度。

为设备状态聚合层提供独立的 `power_ok`、判定有效性、原因和版本，表示当前供能策略是否满足该设备的能源条件。它参与总体在线/离线判定，并在详情弹窗解释，不在状态栏单独显示能源 OK。诊断查询不预留、不消耗能源，不能由于没有新的 IO 事务而失去能源状态更新。

## 验收

- [x] 同一任务重排不会重复执行；设备替换、卸载后旧任务失效。
  （重排=替换，靠「活体表里同键只有一条」这个结构性质；替换/移除/执行时代次回查
  三道检查。**注意「卸载」取 01 的口径＝区块卸载 → 冻结**，另一种读法保留成
  `SchedulerPolicy.invalidate_on_unload`，未替玩法定案。）
- [x] 空闲网络不高频扫描设备；有变化可唤醒，无事件容器可最终被轮询发现。
  （空闲代价是**两次比较**、与设备数无关——睡眠设备不在堆里。唤醒有两条：
  方块实体 tick 只把退避打回初值，`wake(ref)` 才把轮询提前到本帧。
  **「无事件容器最终被轮询发现」只有原语与用例，没有真实消费者。**）
- [x] 假时钟可精确重现低速累积、卡顿和恢复；实际游戏时钟口径另有验证记录。
  （前半句：`drive_once()` 推进时钟、`tick()` 不推进，离线可用
  `clock.advance(n)` 精确控制时间，卡顿与恢复都有用例。
  后半句：2026-09-25 真机实测——`clock.tick = clock.advances = tick_count =
  脚本 tick 脉冲`，四次采样五个计数**完全相等**，时钟每帧一步无漂移；
  频率与暂停行为见交付说明第八节。）
- [ ] 断电不新抽取原料或凭空完成配方；能源恢复后不重复扣费。
- [x] 多网络同时繁忙时都有进展，单次推进不无界处理积压任务。
  （跨网轮转 + 单帧执行上限 `max_tasks_per_frame`；预算按实际消耗递减，
  空闲网络不浪费额度。）
- [ ] 状态层的能源判定与能源服务一致，读取无副作用；断电使非控制器设备状态栏显示离线，详情能区分能源与带宽原因，断电后仍能获取诊断结果。
  （诊断在无能源服务时仍可读这一条**已在 03 覆盖**；其余子句依赖能源增量与 11。）
