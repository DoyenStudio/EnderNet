# 06-06 物品取货口真实缓存增量

2026-10-03。交付服务端路线与离线验证，不代表完整玩法定案或游戏验收。

## 行为与库存权威

- 默认启用：网络 → 本设备 5 格真实容器 → 当前朝向容器；每次主控命令只搬一段，优先输出已有缓存，下次命令再补货。
- 关闭缓存：保留网络 → 朝向容器直输，搬运不读写缓存；已有缓存不清空、不回网、不掉落，重新启用后读取真实库存。
- 每次从 `ContainerProvider` 取当前自身/朝向适配器；自身容器缺失、槽数不为 5 或不可读写时明确阻塞，不能退到隐藏内存库存或绕过缓存直输。
- 以真实容器槽位、物品堆叠上限及完整 `ResourceKey` 为准。外部改槽后读取实际数量，不从 `TransferBuffer` 批次表补回物品。缓冲对象保留旧归属/恢复结构，不能将它的 `total` 解释成取货缓存物品数。配置摘要说明库存以方块容器为准，原生集合负责显示。
- 两段复用 `_pump` 与 `TransferCoordinator`，经过同一主控准入链。部分接收退回该段来源：补货余量回网络，输出余量回缓存；不确定回执由 `PortRunner` 设置 hold，后续轮询不发命令。整个命令重发由主控去重，不能将补货重发当成下一段输出。

## 未定策略与范围

`PortPolicy.output_cache_strategy="demand_first"` 是具名 R05 开发替身，进入 `unresolved_report()` 与 `describe()`，正式验收仍被 `assert_settled()` 拦截：先送缓存、按名单顺序补货；目标缺失/满时不预取，同种余货未送出时不积压；名单移除后的余货保留。其他策略未实现，构造时拒绝。

带货关闭的正式处置、预取与公平补货规则、精确匹配的玩法口径、关闭缓存时的玩家原生槽交互限制仍待定/待接入。该实现只限制自动搬运路线，不能声称原生 UI 或外部模组已被禁止存取缓存。任务 12 的迁移、未完成回执恢复、卸载/拆除善后及跨进程身份未在此交付；不得恢复出第二份实物。06-05 存货口中转、流体 13-03 与 UI JSON 不在本轮范围。
