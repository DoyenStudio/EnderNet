# 08. 合成规划服务

状态：未开始。负责人：待分配。前置：01 的资源模型、05 的库存快照、07 的配方快照；04 提供可暂停的计算预算。

## 目标与边界

把目标资源和数量转换为材料需求、配方批次、依赖关系及预算估算。规划是只读计算，不扣库存、不调用世界 API、不占用真实槽位；09 在提交时复核并预留。

代码归属：`ROOT/server/crafting/planner.py`。参考 AE2 的规划与执行分离，相关入口为 `me/service/CraftingService.java`。

## 接口与交付

`plan(target, amount, inventory_snapshot, pattern_snapshot, policy)` 返回规划任务；`step(budget)` 可继续、取消或完成。结果 `CraftPlan` 包含版本、依赖步骤、批次、原料缺口、预计副产物/余量、提供者候选、槽位与内存估计。

## 分步任务

- [ ] 08-01 按 R11 明确目标语义：区分生产量与目标保有量，确定已有最终产物是否抵扣；在计划结构和订单交互中使用同一口径。
- [ ] 08-02 实现单配方批次取整和库存优先匹配；分开记录现有可用材料、预计产出及不可用的他人预留。
- [ ] 08-03 扩展多级依赖和共享子需求，聚合材料消耗。多产物、副产物和返还物按配方模型记账，避免同一预计产出被重复承诺。
- [ ] 08-04 定义确定性的配方候选优先级；检测当前搜索路径循环，限制深度、节点数和候选展开量，给出可解释失败。
- [ ] 08-05 将计算拆成有状态的迭代任务，支持预算耗尽、用户取消和网络/样板版本失效。
- [ ] 08-06 输出材料清单、缺口和计划摘要，按 R04 的策略估算内存；估计值不作为真实资源已预留的证明。
- [ ] 08-07 向 09 提供计划提交前的复核条件，向 11 提供进度与结果，不向客户端暴露引擎对象。

## 验收

- [ ] 铁镐等多级示例可得出正确批次和缺料清单；同一库存材料不能在两个分支重复使用。
- [ ] 产出大于目标时正确保留批次余量；多产物在依赖中使用时数量守恒。
- [ ] A→B→A 等循环与无基础原料路径能在预算内停止，不卡住服务端。
- [ ] 一次运行与分帧运行的确定性输入得到一致结果；取消不改变任何真实库存。
- [ ] 规划后库存、拓扑或样板改变时，提交端能识别并重验，不依据陈旧快照直接扣料。

## 待定与交接

默认配方优先级与复杂替代配方的支持范围须在接口中明确。循环生产不作为首版自动支持项；无解、缺料和预算超限分别报告，不能统一称为“没有配方”。
