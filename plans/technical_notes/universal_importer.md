# 万用样板采集器

实现位于 `client/ui/universal_importer.py`，屏幕类 `UniversalImporterScreen`
继承 `ToolDeltaScreen`，由 `register_screens()` 登记。资源定义为
`endernet_universal_importer_ui.main`，已在 `_ui_defs.json` 中加载。
`main` 是空白生命周期屏幕，实际显示控件放在独立的 `overlay_panel` 定义中；
动态挂载只能使用 `overlay_panel`，不能复用已注册为 ScreenNode 的 `main`。

## 打开与读取结果

在客户端 UI 初始化完成后，从 `endernet.client` 下的模块调用：

```python
from .ui.universal_importer import open_universal_importer
from .ui.universal_importer_config import get_saved_config

open_universal_importer()
# 玩家按保存后，后续业务可读取：
config = get_saved_config()
inputs = config["inputs"]
outputs = config["outputs"]
```

样板终端的工厂模式已接入 `universal_import_btn`；无配置时点击会关闭终端，
下一 tick 打开采集器。采集完成后，玩家重新打开样板终端，再次点击按钮导入。
重复打开返回现有实例；关闭后再次打开得到新的空白草稿。

`universal_import_btn/ok_img` 通过 `has_saved_config()` 指示是否有已保存配置，
显式保存的空配置也算存在。导入按采集顺序保留前 9 个输入和前 3 个输出，
剩余虚拟槽清空。服务端通过 `template_universal_import` 原子替换两组槽位，
校验工厂模式、配置修订号和物品格式；使用与手动设置新格相同的默认数量。
客户端收到成功回执后才清空全局配置，失败则保留供重试。配置版本号防止旧回执
误清后来保存的新配置；请求在途时不会重复提交。

## 交互与数据

- 默认停止选择、输入模式。开始/关闭选择同步更新 `sample_btn/button_label`。
- 选择期间深度遍历当前栈顶界面的可见控件；原生 `asItemRenderer()` 返回非空、
  `GetUiItem()` 有物品且不是空气时，为其创建覆盖框。
- 自定义屏从空路径根遍历；原生 HUD / 容器的空路径根不可枚举，改从 ToolDelta
  的 `SCREEN_BASE_PATH` 开始。不能将原生界面的空路径 `None` 判为整屏没有物品。
- 每次点击「开始选择」只遍历一次，按渲染控件当时的全局位置和实际大小创建
  覆盖框。没有重复计时器、tick 扫描或点击触发的全屏重扫；格子点击只复核该
  控件的物品与几何信息。操作板位于覆盖框之上，仍可拖动和操作。
- 前 16 个覆盖框立即创建；剩余快照通过下一 tick 回调，每批最多创建 8 个。
  每批仅复核对应控件的物品与几何信息，跳过过期快照，不重新遍历控件树。
  停止选择、切屏、保存、退出或引擎销毁都会清空待创建队列，并递增批次代号，
  防止旧回调在重新开始选择后创建旧框。
- 切屏或屏幕缩放会结束选择并清除覆盖框，保留草稿。翻页、滚动或内容变化后，
  点击「关闭选择」再「开始选择」重新采集；旧物品或旧位置的框不会导入新内容。
- 白色未选；输入橙色，输出淡蓝色。同模式再次点击取消；另一模式点击直接改类。
- 停止选择清除覆盖框，保留草稿；恢复选择按草稿恢复颜色。
- 草稿以界面名称、控件路径、物品 ID/附加值/附魔标志定位。同一物品出现在不同
  控件时可以分别选择；切换界面或物品改变不会把之前保存的选择快照替换掉。
- 保存按选择顺序写入 `universal_importer_config.SAVED_CONFIG` 的 `inputs` /
  `outputs` 列表，关闭采集器并显示 popup「配置已保存」。退出只丢弃本次草稿。
- 每项是 `GetUiItem()` 返回的物品字典（`itemName`、`auxValue`、`isEnchanted`）。
  该接口不提供数量或完整 NBT，不能据此还原完整工厂配方；本轮不生成样板物品。
- 待导入配置仅存在客户端 Python 模块内存中，不写磁盘；点击导入才提交服务端。
  `get_saved_config()` 返回深拷贝，避免后续修改污染保存结果。

## 悬浮生命周期

使用 `CreateUI({"isHud": 1})` 持有采集器生命周期，隐藏它在 HUD 下的原始面板。
实际面板通过 `CreateChildControl` 挂到当前 `GetTopUINode()` 的全屏容器内，
切屏时移除旧面板，下一 tick 在新屏重新挂载，保留草稿和操作板位置。
没有可查询根控件的自定义屏使用默认画布根挂载。绑定前查询操作板、四个按钮
及两个标签是否就绪；挂载最多重试 5 次，每次间隔 0.05 秒，不遍历物品控件树。
宿主节点通过本项目的 `_ImporterScreenHost.screenNode` 显式交给 ToolDelta，
兼容 `GetScreenNodeCls()` 和直接继承 `mod.client.ui.screenNode.ScreenNode`
的模组屏幕；两种类并非同一个继承链，不能依靠 ToolDelta 的实例类型判断。
仅提升 HUD 子控件层级无法跨越教程书等普通屏幕的绘制顺序。
实际根节点为全屏 `panel`，根层级为 100000，
操作板层级为 100；仅 `slot_section/interact_btn` 调整为层级 50。
只有操作板和物品按钮接收操作，其他区域允许操作下面的界面。
采集器不进入 PushScreen 栈，扫描对象仍是 `GetTopUINode()`。

分别使用独立回调静态监听 `PushScreenEvent`、`PopScreenAfterClientEvent` 和屏幕
缩放事件；ToolDelta 同一函数的静态监听只注册一次，不能叠加监听装饰器。
事件仅结束旧选择、清除旧框，并在下一 tick 重新挂载悬浮层、设置层级，不遍历
控件树。监听不随 `OnDeactive` 暂停。普通容器开关不关闭采集器；退出、保存、
引擎销毁或客户端停机时释放覆盖框和草稿，不调用 PopScreen。
切屏后按钮恢复「开始选择」，等待玩家手动重新开始；扫描排除采集面板子树。
