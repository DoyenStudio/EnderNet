# 主动物品存取口：正式规则与验收（2026-11-06）

2026-11-07增补六向放置与旧朝向迁移，新增验收见末节；下方2026-11-06交付数字保留为历史记录。

本文件是总线物品存货口与总线物品取货口的当前契约，覆盖旧文中的未定规则。流体口、被动接口、样板接口不据此改变玩法。

## 规则与实现

| 项目 | 存货口 | 取货口 |
| --- | --- | --- |
| 本机库存 | 5格真实缓冲 | 5格真实缓存，默认启用 |
| 路线 | 外部容器→缓冲→网络；每条命令只搬一段 | 网络→缓存→朝向容器；关闭缓存后网络直输 |
| 名单 | 黑白名单各16个ID，独立保存，新设备默认黑名单 | 最多9个ID，无配置不自动输出 |
| 空名单 | 空黑名单全收，空白名单不主动吸取 | 不取新货，也不自动送出缓存 |
| 匹配 | 只按物品ID判断是否允许主动吸取 | 同ID的不同变体都可供货 |
| 已有余货 | 不受当前过滤影响，优先入网；无朝向容器仍可入网 | 名单移除后的余货原样保留 |
| 玩家和标准外部物流 | 可放入和取出 | 缓存开启可存取，关闭后只可取出 |
| 拆除 | 真实容器原地掉落，脚本不重复生成 | 同左；卸载不是拆除 |

两种主动物品口支持上、下、北、南、西、东六向放置，由放置时的视线决定朝向；只连接朝向的一面，不自动搜索其他邻面。箱子在上方时，需要朝上的物品口；原先朝北的物品口不会因上方出现箱子而自动改向。此定案不扩展到流体口、被动接口或样板接口。

名单仅决定可选资源，真实库存使用完整 ResourceKey，保留 aux、耐久、附魔、命名和 NBT；不同身份不混堆。槽容量由真实容器和单物品堆叠上限决定，不等于固定320件。

按需搬运：存货缓冲未清空不吸新货，吸取前同时探测网络和缓冲空间；取货无目标空间不补货，同ID余货未送完不继续囤积。每种ID与其元数据变体均轮转，稳定顺序为ID和完整键的规范文本顺序，跳过不能搬运的候选。取货补入缓存不推进供货游标，送达后才推进。配置变化清理游标；正常保存恢复保留游标。

所有搬运复用主控制器准入、供能、带宽、额度、事务回执和去重。部分接收退回本段来源，不确定结果暂停并保留待核对记录。存货仅在缓冲实际入网时产生外部回流计数，吸入缓冲不计数。

## 配置、同步和恢复契约

- `port_configure` 命令不变。`PortConfig.item_filters` 为 `{blacklist: [资源键字典], whitelist: [资源键字典]}`；仅物品存货口使用，其他角色为 null。`filter` 是当前模式名单的兼容视图。
- 切换 `filter_mode` 读取对应名单；提交 `filter` 更新请求指定模式（缺省为当前模式）的名单。其他字段仍按补丁合并；服务端校验两份名单，而非只检查正在显示的那份。
- 旧配置保留原模式：把旧 `filter` 按ID去重后迁入该模式，另一份为空。缺失旧模式按原来的白名单解释；新放置设备才默认黑名单。每份最多16项，超限旧档冻结并保留，不截断。
- 配置视图和协议新增 `item_filters`；客户端预览、失败回滚、权威推送一同支持。并发修改采用服务端接受顺序；编辑名单附带模式，避免写入另一个模式。不是乐观版本锁。
- `PortState.cursor` 随归档保存；旧档缺失时初始化为空。真实库存只由网易容器保存，禁止按批次台账补出第二份实物。
- 六向放置使用 `minecraft:facing_direction`，世界适配优先读取它，其他设备仍兼容水平 `cardinal_direction`。接口载荷版本3标记已完成朝向迁移：旧版本1/2的两种物品口按归档朝向更新真实方块状态并回读确认，保留旧水平朝向和库存；确认失败则保留原记录并冻结，不接受引擎重新解释旧aux后的错误方向。版本3恢复以世界当前朝向为准，不反复套用历史朝向。
- 未知版本、损坏配置和非法游标冻结自动搬运，保留原记录，不允许普通清除待核对命令解除版本冻结。拆除并重放不继承旧配置。
- 冻结保护按存档位置保留；原记录无法安全读取时，同位置拆除重放或更换接口型号仍停止搬运并拒绝覆盖配置，等待原记录处置。
- UI沿用原生容器集合，新增 `#EnderNetPort.hint` 标签：失败原因、空名单语义、关闭缓存只可取出。取货摘要采用首项图标＋已设定N项，空配置 barrier。不能禁用整个网格，否则无法取回余货。
- 配置视图增加只读 `facing_status`，由服务端探测当前朝向容器，下发给 `#EnderNetPort.facing`；替换原来的静态“未接入”占位。主面板高度从200增至214，为提示留出独立行。
- 玩家放入、漏斗输入及本模组引擎容器适配写入共用服务端拒收判断。第三方绕过事件直接改槽无法全面阻止；下一轮始终读取真实库存，不凭旧台账覆盖它。
