# ResourceKey 文本身份缓存（2026-10-05）

## 约定与实现

- `canonical()` 首次生成文本后保存在实例 `_canonical` 槽位；身份格式与存档格式不变，缓存不写入 `to_dict()`。
- `_kind`、`_name`、`_aux`、`_identity`、`_raw` 初始化后禁止再次赋值或删除。逐槽首次赋值允许 copy/deepcopy 在新对象上恢复。
- 身份变化必须构造新键，并由业务层处理旧键、新键的库存与索引变化。仓储 dirty 表示库存视图变化，不承担身份缓存失效。
- `_raw` 仍是私有载荷字典，未实现递归冻结；业务调用方只能通过返回深拷贝的公开接口访问。规范身份 `_identity` 是不可变元组树。直接篡改私有载荷不受支持。
- 未修改预留扫描算法（方案 B/C）。每个调用过 canonical 的实例会额外保留一份文本。

## 离线验证

- 资源相关 164 项通过，新增覆盖暖缓存不再编码、身份写入/删除保护、冷/暖 copy/deepcopy、物品/流体、序列化还原。
- 全量 3891 项：2 个失败、1 个错误。119 个运行时文件通过 Python 2.7 语法门禁。
- 将修改前 HEAD 的 resource_key 模块加载到独立测试进程，复现相同三项问题：订单提交、空过滤名单、预览行 JSON 缺少 text。未修改这些既有问题。
