# 持久化后端与引擎落盘实测

日期：2026-09-29。对应任务 12-02。**本文记录的是真机实测到的引擎行为，以及
据此选定的后端**，不是设计意图。没测过的一律在第 6 节点名，不混进结论。

探针环境：运行版本 `3.9.0.401155`，世界 `MC_DEV_WORLD`，py2.7.13。
探针脚本是临时的、没有入库；读数与结论留在这里。

## 1. 三条落盘路径互不相同

物品 `userData`、世界 `ExtraData`、方块实体数据是**三套独立的序列化**，
大小限制、保存时点、返回值语义都不能互相类推。12-02 要求逐条核实，结论如下。

## 2. 物品 `userData`

### 2.1 单字符串硬上限 32767 字节，超限是**断言**不是报错

引擎 `DataIO::_writeString` 里有 `v.length() <= 0x7fff` 的断言（0x7fff = 32767）。
超过时**写入毫无征兆**：`SpawnItemToContainer` 返回 `True`，`GetContainerItem`
也能把 1 MB / 4 MB 的字符串完整读回来；**错误只在保存序列化时才现形**，
表现为模态断言框（中止/重试/忽略），挡住主线程。

→ 任何写进 `userData` 的单个字符串都必须远小于 32767 字节。
这是**逐字符串**限制，不是整份 NBT 的总量限制；总量上限没有测过，
因此**不能**当成「拆成小串就安全」。

### 2.2 介质内容装不进物品

按型号装满实测的载荷大小（`Medium.to_dict()` 的 JSON 字节数）：

| 型号 | `max_types` | 条目数 | 载荷字节 | 每条约 |
| --- | --- | --- | --- | --- |
| `endernet:singleside_tape` | 12 | 12 | 2963 | ~217 |
| `endernet:database_compressed_tape` | 64 | 64 | 12144 | ~144 |

单看数字，12 KB 离 32767 还有余量。**但不据此把内容放进物品**：

- 型号是可扩展的，`max_types` 一旦调大就会撞上限，而**撞上限的表现是存档时断言**
  而不是写入时报错（§2.1）——这是最坏的失败形态：写的时候一切正常，存档时炸。
- 内容的真身在驱动器里，而介质物品会被玩家拿在手上、放进箱子、跨网络转移。
  每次交接都随物品搬一遍全量内容，等于把权威数据复制成多份。
- 12-03 要求的是「拔插后同一介质内容跟随身份」——**身份跟随即可，不必内容跟随**。

→ 物品只携带身份、格式版本与展示载荷；权威内容放世界记录（§3）。

### 2.3 `unicode` 值被静默丢弃

写进 `userData` 的 py2 `unicode` **值**会被引擎丢掉，连同它的键；兄弟项与其他
列表元素完好；`unicode` **键**被转成字节串，正常。非 ASCII 的 UTF-8 字节串
（`中文`、`§6剩余种类数：3`）**字节级原样**。

→ 写进 `userData` 的一切文本都用 py2 `str`。介质 ID 与标记串都是纯 ASCII，天然满足。
完整读数与路径范围见 [resource_identity.md](resource_identity.md#容器-userdata-的三条实测事实2026-09-25任务-07-真机py2713)。

### 2.4 容器路径与背包路径表现一致

2026-09-29 在背包路径（`SpawnItemToPlayerInv` / `GetPlayerItem` / `SetInvItemNum`）
复测了 §2.3 与 Lore 往返，结果与容器路径**一致**：`unicode` 同样被丢弃、
Lore 同样字节级原样。背包路径的三个原语此前从未在真机跑过，现在都有了读数。

两条路径共同的读回形状：**嵌套容器不包装，叶子标量包装**成
`{"__type__": T, "__value__": V}`；空槽读回 `None`（不是空气字典）。

## 3. 世界 `ExtraData`：选定的后端

### 3.1 会落盘，有直接证据

64 KB 的单键值写入后读回完全一致，且**确实进了磁盘**——标记串 `ENPROBE7Q2Z`
在世界目录 `db/*.log`（leveldb WAL）里直接 `grep` 到了。这是**直接证据**，
不是从 API 返回值倒推的。

上限没有探到；4 MB 量级在内存侧接受过。按 §2.2 的表，单块介质内容 ≤ 12 KB，余量充足。

### 3.2 保存开销 ≈ 39.8 KB 固定 + 载荷，**每次调用**都付

| 载荷 | WAL 增量 |
| --- | --- |
| 很小 | +39840 |
| 1.8 KB | +39910 |
| 64 KB | +105314（≈ 65536 + 39778） |

固定部分与载荷几乎无关，是**每次调用**的代价。
→ **必须批量合并**：每笔业务一次 `SaveExtraData()` 是纯浪费。12-08 的脏写合并
不是优化项，是必需品。

### 3.3 `autoSave=False` 只有 `SaveExtraData()` 能提交，且提交是**异步**的

两个标记对照实测（相隔约 100 秒，期间 WAL 还轮转过一次）：

| 写法 | 结果 |
| --- | --- |
| `SetExtraData(k, v, False)` + 不调保存 | **不在盘上**——引擎自己的周期性存档不会带走它 |
| `SetExtraData(k, v, False)` + `SaveExtraData()` | 在盘上（稍后才出现） |

- `autoSave=False` 是**真延迟**，不是「等下次自动存档」。
- `SaveExtraData()` 是唯一的提交点，而**返回 `True` 不等于已落盘**：调用返回后
  立刻查 WAL 一个字节都没涨、标记也 `grep` 不到，过一阵才出现。

运行期反汇编佐证：`SetExtraData(key, value, autoSave=True)` 的 `co_names` 显示它
写完后确实调了 `mExtraData.Save()`，与显式 `SaveExtraData()` 是同一个调用——
**两者都只是「提交」，都不是「落盘」**。

→ 「已提交」与「已持久」之间有一个窗口。12-05/12-06 要「区分正常退出恢复和外部
交接崩溃窗口」时必须以它为前提：**不承诺任意时刻崩溃精确一次**。

## 4. 方块实体数据

不需要在本任务定案：介质内容是**跨位置**的（物品被拔下来带走），而方块实体数据
位置绑定，做不了介质内容的后端。它的结构性约束（不嵌套赋值、键须为 `str`、
list 元素须同构、不支持 tuple、超出 int32 的整数失败）记录在
[netease 组件文档]里，与任务 05 的设备侧存档相关，由那一边的验收覆盖。

## 5. 后端选择

**物品携带身份与展示；权威内容按介质 ID 存进世界 `ExtraData`，一块介质一个键。**

- 键：`endernet:medium/<id>`，即 `Repository` 的 `(kind, record_id)` 映射为
  `endernet:<kind>/<record_id>`。**一块介质一个键，而不是一整块大 blob。**
  理由：运行版本的 `SaveLevelData` 有按 key 增量落盘的分支
  （`set_level_script_data_by_key`）与 `TrackedDict` 脏键跟踪，
  一块介质一个键才让「只有这几块脏」变成真的省（§3.2 的固定开销按调用次数付）。
- 与 §2.2 的配合：物品里的 `endernet:medium` 只放 `{"id": ..., "v": ...}`，
  大小与内容无关，型号再怎么扩也不撞 32767。
- 与 §3.3 的配合：提交点集中在 12-08 的合并写，不放在每笔交易里。
- 替代方案（内容进物品 NBT）的失败形态见 §2.1 与 §2.2，不再重复。

介质身份本身的编码（稳定 ID 字段、重复检测、空介质堆叠）与容量行的归属标记，
见 [medium_lore.md](medium_lore.md#2-身份比较与物品还原)。

## 6. 没测的

- **方块实体数据的大小上限**：故意没测，理由见 §4。
- **leveldb 的 fsync 耐久性**：LevelDB 默认不 sync，因此 §3.3 那个「已提交未落盘」
  窗口在断电场景下有多宽没有读数。**在拿到读数之前不要承诺掉电精确一次。**
- **经 tooldelta 物品包装层写 `userData` 的路径**：本文读数全部是引擎直连路径。
  `resource_identity.md` 记的旧读数来自包装层且与直连不一致，那条路没有重测，
  走它的功能仍应假定旧读数成立。
- **原生 tooltip 的目视效果**：悬停渲染不能自动驱动，待人工确认（见 medium_lore §2）。
- **玩家背包路径上的 `customTips`**：它会被引擎从顶层搬进 `userData["ItemCustomTips"]`
  （见 `resource_identity.md` 末段），影响 05/06 的守恒核对，此处未测。
